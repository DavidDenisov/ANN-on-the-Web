# Revision and remaining evidence

This revision combines the reorganized implementation with the alternate paper draft and addresses the supplied WWW demo review. Measurements from the original runs are preserved. New derived statistics and fresh screenshots are identified separately.

## Incorporated from the alternate draft

- The routing explanation now distinguishes isotropic passage perturbations from real-question retrieval and the encoder's question–passage distribution gap.
- Transformers.js is cited, and the I-BERT citation is removed from the custom symmetric INT8 format.
- Wilson intervals are computed from exact retained success counts. The alternate claim that all intervals are within ±0.35 percentage points is discarded: at 83.51% the interval is much wider. Default SQ6 is 9,806/10,000, with a 95% Wilson interval of 97.77–98.31%. These are marginal sampling intervals, not a paired significance test between codecs.
- Bibliographic spelling for Krishnaswamy and the NeurIPS name is corrected.

## Review points addressed

1. **Quality metric.** The abstract specifies four probes, 32k clusters, SQ6 and noise magnitude 0.4. The metric explicitly does not establish real-question recall@10, relevance, or q8 query-encoder quality. A displaced source can cease to be the exact nearest neighbor; the plateau cannot be attributed solely to routing or solely to noise without exact search for those queries.
2. **Latency scope.** The 130.3/150.3 ms numbers remain explicitly one fixed question, 100 warm-ups and 1,000 timed repetitions, with startup and DOM rendering excluded. Its vector bytes are about 38% below the varied synthetic workload. No varied end-to-end estimate is obtained by adding unrelated component means. Browser-cache bypass is distinguished from a cold CDN or connection. The original seeded configuration shuffle and supplemental recorded shuffle replace “order was not fixed.”
3. **Positioning and baselines.** SPANN and Tiptoe are added from publisher/Crossref bibliography metadata; Pagefind and sql.js-httpvfs are linked to their official projects. The contribution is an interactive static-Web deployment, not a novel ANN algorithm. A 48-byte PQ code-budget illustration yields 1.69 GB and about 505 fixed-payload searches, or 413 at the synthetic vector-only mean. This is not an equal-quality baseline. Publisher egress of 3.25 TB per million fixed-payload searches is explicit.
4. **Privacy.** The threat model assumes trusted served client code and names the host/CDN's view: IP, timing, selected cluster IDs and 500-passage text-batch IDs. It distinguishes likely-result leakage from proof that a visitor read a particular result. Larger batches, decoys and PIR are discussed without claiming unimplemented protection. The source UI includes the same access-pattern notice.
5. **Artifacts and durability.** The placeholder is replaced with the user's real GitHub repository. The source and PDF are published there. The 1,000-file batch is identified as an implementation choice rather than a 20,000-file platform limit. Object-storage migration and archive contents are documented. No permanent hosting or archive DOI is promised. Wikipedia attribution and the dataset's missing separate license declaration are documented in `DATA-NOTICE.md` and the paper.
6. **Demo presentation.** The stylized panels are replaced by actual October 30 public-page captures at 1440×960 CSS pixels and 2× pixel density. The earlier ten-query UI is no longer shown; the actual current lab fixes 10,000 queries. Screenshots contain genuine page state: a ten-result search, and a ready lab before a run. Capture timings are not reported as benchmark results. Source HTML adds startup/high-probe and large-lab-run bandwidth notices. These HTML notices are committed but not deployed to the existing CDN by this GitHub publication.
7. **Minor accuracy points.** Four to eight FP16 probes increases mean time 1.78× and vector bytes 1.96×. The one-versus-four demo is described as a walkthrough, not claimed to appear in the search screenshot. FP16/SQ8/SQ6/INT8 differences are not asserted significant. SQ4's observed fetch implies 468 Mbit/s; the separate 300 Mbit/s speed test was not a bandwidth cap. No causal explanation of that variation is fabricated. Number formatting is standardized in displayed sample counts.
8. **Skew and vector compression.** New descriptive statistics from public manifests cover all three cluster counts. At 32k, cluster sizes have median 1,023, p95 2,188 and max 8,263 passages. Summing the four largest gzip files gives a conservative 19,322,757-byte bound at four probes, not an observed query tail. Public manifest URLs, SHA-256 identities, quantile convention and retained size fields make these statistics auditable offline. SQ8/PQ passage compression and rescoring are discussed as unevaluated trade-offs.
9. **Space.** The main count table shows the three four-probe settings, while the seven-setting 32k plot carries the probe comparison and confidence intervals. All original nine count/probe measurements remain in the committed CSV. The four-page PDF preserves standard ACM fonts and margins.

## Evidence still required before claiming full review resolution

- **Real-question ANN recall@10.** Supply a fixed, licensed set of human questions and the full local passage vectors. Embed questions with the pinned q8 browser model; record the exact query vectors. Obtain full-corpus exact top-10 with the same normalization/metric and documented tie handling, then compare ANN top-10 for 1/4/8 probes using those identical vectors. Report overlap/10 with uncertainty across queries. Use relevance judgments separately; nearest-neighbor overlap is not semantic relevance. The supplied compact artifact has neither that query set nor the full local corpus, so no real-query recall is claimed.
- **Varied complete-query timing.** Use a recorded real-question schedule and the production ten-result worker, preserving raw per-query embeddings, vector/text byte counts, selected clusters, component times and directly measured totals. Report mean, nearest-rank p95 and max. Randomize settings with a saved seed; distinguish warm-worker measurements from fresh-context first query. Preserve startup separately.
- **Cold/mobile conditions.** Run a fresh process/context with no browser cache, and use a defined network/CPU throttle or physical mobile device. Record DNS/TLS and connection reuse. A client cannot guarantee a cold CDN without provider control or a verified cache-status protocol, so label any uncontrolled first-visit result accordingly. No new cold-CDN or mobile measurements were fabricated.
- **Measured server and compressed-index baselines.** Match corpus, query encoder, metric, returned texts and quality target; include server compute and client startup/storage. The byte crossing in the paper is an analytical illustration only.
- **Byte tails and privacy attack.** The cluster bound is not a p95/max from a real-query trace. Quantifying semantic inference or result identification from request patterns needs an explicit attack and held-out queries.
- **Archival and licensing.** Make an immutable deposit of deployable manifests/build inputs and clarify the embedding dataset license. GitHub publication alone does not archive tens of GB of hosted data.
- **Optional presentation additions.** An exact-search comparison in the UI and a recorded screencast remain unimplemented. Screenshots are the actual connectivity fallback, not described as a video.
