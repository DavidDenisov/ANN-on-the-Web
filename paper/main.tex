\begin{abstract}
We demonstrate browser-based approximate nearest neighbour (ANN) search over $35.2$ million English Wikipedia passages hosted on a static CDN. The browser embeds questions locally, uses inverted file (IVF) routing to select vector clusters for parallel download, ranks their vectors, and fetches text for the top results. This avoids a full index download or an application search server. Visitors submit questions and inspect passages, timings, and download costs; a companion lab measures the recovery--bandwidth trade-off. On a desktop with primed CDN caches, at 32k clusters, SQ6 centroids, and four probes, a repeated fixed question returning ten passages averages $130.3$~ms to worker reply, including embedding and text loading, with $3.25$~MB of compressed payload. Worker startup averages $2.46$~s. At the same settings, synthetic perturbations of L2 magnitude $0.4$ yield $98.1\%$ source recovery@1; this is not real-question recall. Queries and embeddings stay local, while file requests can reveal access patterns.
\end{abstract}

\section{Introduction}
Semantic search on a static document collection usually requires a search service or a large local index. We demonstrate browser ANN over $35.2$ million passages without either: local inverted file (IVF) routing selects remote cluster files for parallel download. The probe count controls the number of clusters fetched and ranked.

Our contribution is a static-Web deployment and an interactive view of established ANN techniques: search exposes per-question costs, while the lab isolates routing and centroid compression. The FP16 vectors occupy about $27$~GB; each query transfers only selected clusters and result text from Cloudflare Pages.

\subsection{Related work}
SPANN~\cite{spann} keeps centroids in memory and posting lists on disk; we apply this partitioned-search pattern to static HTTP files. Tiptoe~\cite[Sections~3--5]{Tiptoe} also embeds queries and selects clusters locally, but its servers compute encrypted similarities over the corpus to hide cluster selection, followed by private URL retrieval. Our client downloads selected plaintext vector files and ranks locally, trading cryptographic privacy for static serving. Selective loading also appears in \href{https://pagefind.app/}{Pagefind}'s lexical search and \href{https://github.com/phiresky/sql.js-httpvfs}{sql.js-httpvfs}'s range-based database reads.

MeMemo~\cite{MeMemo} and WebANNS~\cite{WebANNS} use browser-local HNSW in RAM and IndexedDB; DiskANN~\cite{DiskANN} uses graph traversal. WebANNS evaluates up to $480{,}000$ passages. Our larger remote corpus uses parallel cluster reads; the ANN algorithm is established.

\section{Demonstration scenario}
\label{sec:demo}
The two public pages use the same Wikipedia passage collection.

\paragraph{Wikipedia search.}
Visitors enter a question or other text and receive ranked passages with links to Wikipedia articles. Defaults are 32k clusters, SQ6 centroids, four probes, and ten results. Controls offer three cluster counts, six centroid formats, and $1$--$100$ probes. The page reports embedding, centroid loading, retrieval, and text-loading times alongside vector downloads. The presenter first runs the example question in Figure~\ref{fig:search-demo}, compares one and four probes, and inspects changed passages and byte counts. Visitors then try their own questions; these examples illustrate behaviour, not relevance scores. We keep the walkthrough to one or four probes to limit downloads; queries can be cancelled.

\paragraph{Clustering lab.}
The supplied lab (Figure~\ref{fig:lab-demo}) offers noise presets and separate checks for cluster count, probes, and centroid format. Visitors select $1$--$10{,}000$ precomputed perturbed-passage queries per configuration (default $10$) and can cancel runs. Short runs uniformly sample a shared subset; small samples illustrate behaviour. Paper measurements use all $10{,}000$ queries, excluding embedding. Probe and compression checks use 16k clusters; the paper adds a 32k supplement. Full checks can take hours and transfer hundreds of GB. At the poster, visitors try short checks and interpret retained tables and the probe plot.

\section{Method outline}
Figure~\ref{fig:method} traces local computation and the static files downloaded at startup and during search.

The Maloyan dataset~\cite{wiki-minilm} provides the passages and their $384$-dimensional \texttt{all-MiniLM-L6-v2} embeddings~\cite{minilm-model-card}.

For queries, Transformers.js~\cite{transformersjs} loads the Xenova ONNX conversion~\cite{xenova-model-card} in \texttt{q8} format, truncating inputs to $256$ tokens.


\paragraph{Index preparation.}
We train $C$ centroids with Faiss $k$-means~\cite{Faiss}, using $20$ iterations on about $2.1$ million uniformly sampled passages. We assign each passage to its nearest centroid and store its ID and FP16 vector in that centroid's gzipped file. Centroids are published in FP16 and compressed formats; SQ6 uses six-bit scalar quantisation per component. Passage vectors remain FP16, occupying about $27$~GB before compression.

\paragraph{Result text.}
Brotli files hold $500$ contiguous passage IDs each, except the last. These text batches are shared across cluster counts. The browser fetches result batches and keeps decoded text in an $8$~MiB cache.

\paragraph{Static hosting.}
The $70{,}336$ text files use $71$ branch deployments; vectors and centroids use $59$ more in a second Pages project. Manifests map files to URLs. Our $1{,}000$-file upload batches are a packaging choice, below the provider's \href{https://developers.cloudflare.com/pages/platform/limits/}{$20{,}000$-file Free-plan ceiling}. Object storage can replace these hosts through manifest updates preserving CORS, content-encoding, and worker-isolation headers.

\section{Supporting evaluation}
\label{sec:comparison}
All three indexes cover $35{,}167{,}920$ passages. We test routing with synthetic perturbations and the ten-result worker workflow with a fixed question.

\paragraph{Query setup.}
Configurations share \BenchmarkQueryCount{} uniformly sampled distinct source passages. We add $v\in\mathbb{R}^{384}$ with uniformly random direction and $\|v\|_2=\alpha=0.4$ to each unit source vector, then renormalise. The lab also offers $0.05$ and $0.15$.

\paragraph{Perturbation scale and scope.}
On $1{,}000$ sources, mean query-source L2 displacement is $0.378$, or $55.5\%$ of the mean nearest-neighbour distance ($0.681$) from an exact full-corpus scan excluding self matches. This controlled test exercises IVF boundary routing; isotropic passage noise does not model the question--passage distribution gap.

\paragraph{Metric.}
\textbf{Source recovery@1} is the fraction of perturbed queries whose source ranks first. Noise can favour another passage even in exact search; the plateau is not an ANN recall ceiling. Real-question recall@10, relevance, and q8 query-encoder effects remain unevaluated. For SQ6 at four probes, the $95\%$ Wilson interval~\cite{wilson1927} is $[\DefaultRecoveryLow{},\DefaultRecoveryHigh{}]\%$ ($9{,}806/10{,}000$), describing uncertainty under this synthetic protocol.

\paragraph{Test environment.}
Experiments use Ubuntu~22.04 on an Intel Core i5-12400F PC with 32~GB RAM and a GTX 1660 SUPER GPU. GPU Faiss prepared the indexes. Browser experiments use Chromium~155; inference uses Transformers.js~4.3.1 with CPU-only WebAssembly and four threads. Separate \href{https://fast.com/}{FAST.com} checks reported about $300$~Mbit/s download; CDN throughput was uncontrolled.

\paragraph{Embedding compatibility.}
Re-embedding $1{,}000$ uniformly sampled passages with the q8 browser encoder yields mean and 5th-percentile cosine similarities of $0.9924$ and $0.9892$ to the stored vectors; this passage check does not validate question retrieval.

We compare $C\in\{8{,}192,16{,}384,32{,}768\}$ with 1, 4, and 8 probes. At 32k, we sweep 1, 2, 3, 4, 6, 8, and 10 probes, and compare six centroid formats at four probes: FP16, SQ8/SQ6/SQ4 and symmetric INT8~\cite{Faiss}, and PQ4 with 4-bit codes per eight-component block~\cite{product-quantization}. Cluster assignments and FP16 passage vectors stay fixed. Shared configurations run once.

\paragraph{Hosting and timing.}
Vector and text files are fetched before timing to prime the CDN cache; the fixed-question run uses $100$ preliminary searches. CDN residency and connections remain uncontrolled; cache bypass does not establish a cold CDN. Timed searches fetch up to ten clusters in parallel. Timed fetches bypass browser HTTP caching, and text loads also bypass the decoded-text cache; untimed accuracy checks allow cached cluster files.


Retrieval time covers routing, cluster download, decompression, decoding, and ranking; Section~\ref{sec:client-costs} reports startup and complete-query costs. Centroids load once per configuration; separate download/decode benchmarks use \BenchmarkCentroidSamples{} trials per file. Tables report mean and 95th-percentile times (p95), and gzipped vector payload in decimal MB ($10^6$ bytes). Configuration order was randomised; the original seed and shuffled supplement order are recorded.

\subsection{Client setup and query costs}
\label{sec:client-costs}
\paragraph{Complete ten-result query.}
For ``How do plants turn sunlight into energy?'', the client returns ten passages at 32k/SQ6 and four probes. Across $1{,}000$ repetitions, search submission to worker reply takes $130.3/150.3$~ms (mean/p95), including embedding, vector retrieval, text loading, and message handling. Startup and DOM rendering are excluded; model and decoded centroids stay loaded. This repeated fixed-question p95 measures jitter, not variation across questions. The results require $2.48$~MB of gzipped vectors and $0.77$~MB of Brotli text ($3.25$~MB total payload, excluding HTTP headers).

\paragraph{Separate components.}
For synthetic queries, top-1 retrieval at 32k/SQ6 and four probes takes $122/187$~ms (mean/p95), with $98.1\%$ source recovery and $3.98$~MB of vectors. The fixed question transfers about $38\%$ fewer vector bytes; these component runs cannot be added to estimate varied-question end-to-end latency.
\paragraph{Startup.}
Startup spans worker creation until the model and 32k SQ6 centroids are ready, excluding page navigation. Across $100$ fresh browser contexts (reusing the Chromium process), it takes $2.46/2.53$~s (mean/p95). The model ($23.7$~MB), WebAssembly runtime ($14.3$~MB), and centroids ($9.0$~MB) total about $47$~MB. Browser caching is bypassed; loading phases overlap.

\subsection{Trade-offs and limitations}
A hypothetical $48$-byte/vector PQ index needs $1.69$~GB for codes alone. Equating this with $47+3.25Q$~MB gives about $505$ queries. This illustrates byte budgets, not equal-quality or latency baselines: IDs, codebooks, caching, and storage overhead change the crossing. One million uncached fixed-question searches transfer $3.25$~TB before startup or headers. A server returns text alone but receives the query and needs search compute; that baseline is unmeasured.

FP16 passage vectors dominate transfer. SQ8/PQ passage codes with optional rescoring could reduce it, but change ranking and require evaluation. At 32k, manifest cluster sizes have median $1{,}023$, p95 $2{,}188$, and maximum $8{,}263$ passages. The four largest gzip files sum to $19.32$~MB, an upper bound at four probes, not an observed query percentile; byte tails remain unmeasured. Varied real-question end-to-end mean/p95/max, cold-connection and cold-CDN trials, and throttled/mobile profiles remain necessary before generalising the desktop timings.

\paragraph{Privacy threat model.}
Assuming trusted client code, query text and embeddings stay local. The host/CDN can link IP addresses and timing to four of $32{,}768$ cluster IDs and text-batch IDs. For uncached requests, intersecting these batches with downloaded candidate IDs can identify returned passages and potentially reconstruct the displayed result set; inference effectiveness is unmeasured. Displayed results do not establish which passages were read. Co-locating text with vector clusters would mitigate this additional leakage by eliminating result-specific text requests; selected clusters would remain visible. We retain shared ID-based text batches for simplicity while varying cluster count: co-location would require separate text layouts per count and was not implemented or evaluated. PIR, as in Tiptoe~\cite{Tiptoe}, requires a different serving protocol.

\section{Conclusion}
Local IVF routing enables browser search over $35.2$ million statically hosted passages. The demo exposes source recovery, latency, and bandwidth trade-offs.
